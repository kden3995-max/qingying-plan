# 第一阶段游客模式验收

更新：2026-10-25。第一阶段实现分支 `feature/memory-guest-mode`，基线 `59a6a14`（文件树与此前 UI 提交 `0f8e72e` 相同）。最初仅在本地完成；随后用户授权只发布第一阶段纯游客版本。本文记录实现验证，发布前检查及回退点见 [发布记录](release-preflight.md)，实际部署结果另以对应 Pages 工作流和线上验收为准。

## 实现范围

移除了 UI 启动自动恢复、资料／记录自动写 localStorage，以及多页面自动合并数据的路径。游客 state 仅存在页面闭包内存，手动导出／导入保持原格式。`app.js` 与 `features.js` 相对基线逐字节不变：计算、饮食运动细节、健康适用限制、日期与备份校验保持原样。

按最新要求移除了全站顶部游客横幅。首次首页仅在主按钮下方简短提示；离开首页后同一文档不重复提示，未写入存储。页脚、手机菜单及记录区保留结束入口，记录／备份附近按需提示，详细隐私说明默认折叠。沿用现有按钮、配色、卡片及分屏布局。旧版数据管理位于记录区，提供明确的确认恢复／删除，默认仅检查键是否存在，不读取值或展示健康字段。默认不创建云匿名账户，没有假登录、后端 SDK、云数据库请求或新密钥配置。

## 实际执行的命令

- `npm test`：12 项通过（计算／饮食运动、健康限制、备份、日期趋势、旧版工具、路由）。
- `npm run test:browser`：21 组通过（1 组提示位置、9 组游客隐私、3 组分屏／响应式、8 组实际功能）。
- `npm run test:pages`：同样 21 组在 `/qingying-plan/` 挂载路径通过。
- `node --check ui.js`、`git diff --check` 通过；核心文件与基线无差异。

浏览器为本环境 Chromium／Playwright，使用独立测试上下文和合成数据，无用户真实资料。原有自动保存／刷新恢复／多标签页同步断言因需求明确改变而替换为“内存更新、刷新清空、页面互不共享”，不是继续保留已过时行为。

## 已实际验证

| 用户验收项 | 结果与证据 |
| --- | --- |
| 新游客、刷新、重新打开为空 | 已测：有旧数据时隐藏表单也不填值；刷新和新页面回首页、资料及记录为空 |
| 不写浏览器存储 | 已测：生成、记录、打卡、感受和示例均无 localStorage/sessionStorage 写入；旧数据的 getItem 在确认前调用次数为 0 |
| 两个同时打开的游客页面 | 已测：同一浏览器同一站点，两页记录彼此不更新；storage 事件不恢复或合并个人数据。此项不是账户 A/B 的服务端授权测试 |
| 结束后无页面残留 | 已测：内存导出的状态为空，资料、健康勾选、输入草稿、结果／说明、记录／感受、图表和导入预览均被清除；返回首页，连续返回四个旧历史条目仍为空 |
| 页面缓存恢复 | 已测真实 Chromium BFCache：跨文档离开后返回，观察到 `pageshow.persisted=true`，仍为空并回首页；恢复前内容遮蔽、页面不可交互 |
| 页面冻结／恢复 | 只验证了合成 `freeze`/`resume` 事件下的应用清理逻辑；未声称进行了操作系统实际冻结测试 |
| 清理期间交互 | 已测：故意延迟餐食图片加载，使初始化未结束，此时旧数据恢复不能打开隐藏对话框；清理完成后正常可用 |
| 在途导入 | 已测：结束后才完成的 File.text 不弹旧预览、不覆盖下一位游客；结束前打开的文件选择器晚选文件也会被忽略 |
| 旧版恢复／删除 | 已测：先显示不含健康数据的确认，取消不读值；确认后只恢复本次内存、替换而不合并。旧副本保持原样；单独删除只移除旧键，其他键不受影响 |
| 存储被禁用 | 已测：旧数据管理提示受限，正常游客生成、记录及结束仍可操作 |
| 第一阶段失败处理 | 已测：旧数据损坏、删除失败、无效备份、导出不可用、体重输入被拒绝；原数据及必要输入保留，有明确反馈，不伪报成功 |
| 原有功能 | 已测：三步填写与错误焦点、返回修改、待更新提示、重新生成、一周三餐／替换与动作、健康限制暂停、同日覆盖／删除、真实日期图表、打卡、感受、完整备份的预览取消／确认 |
| 手机与桌面 | 已测 320／390／430／768／1440px 的主要分屏，无页面横向溢出；主要按钮触控尺寸、键盘跳转、焦点、减少动态效果检查通过 |
| 网络与脚本 | 实际功能／导航套件未观察到外部资源请求、云端写入或页面脚本异常，资源 404 也作为失败检查 |

机器可读隐私结果：`artifacts/guest-privacy-results.json`。其中 BFCache 明确记录 `actualBFCacheRestoration:true`，冻结事件明确标记为 synthetic。界面截图在 `artifacts/guest-mode/`，已打开检查手机首页及桌面结果，保留原有 UI 结构并增加游客提示。

## 清理与兼容边界

站内返回修改属于同一次游客体验，会保留内存草稿；跨文档离开、刷新及缓存恢复会结束体验。旧版浏览器副本只有明确选择删除才会移除，不在游客结束时偷偷删除。工具无法鉴定旧副本的真实所有者，因此恢复前明确提示可能属于其他使用者。

本工具能清理的是自己控制的页面对象、DOM、预览和操作；无法删除用户已导出的文件、浏览器内部取证痕迹或系统截图，不宣称设备级安全擦除。所有浏览器兼容性和真实账户验收都须分别完成。
