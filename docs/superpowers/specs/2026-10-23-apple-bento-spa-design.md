## 数据与隐私约束

现有数据结构为 `{version:1, profile, records, checkins, habits}`，存储键为 `qingying-state-v1`。保留该键、版本、字段、读写时机和原有范围限制。

数据按同一站点的浏览器存储空间隔离，没有账号级存储、上传、云同步或登录。清空浏览器数据会失去记录，跨设备靠原有 JSON 备份迁移。UI 改版不增加健康信息上传、分析追踪、Cookie、其他存储键或第三方服务。

示例计划与真实记录分开：首页不把示例资料当成用户资料；结果预览中的 75→70 kg、12 周、0.4 kg／周及 BMI 26.0 均标为示例。未有体重记录时显示空状态，不画虚构曲线、不把计划起始体重当作一次称重。

## 目标与边界

用苹果健康式的可读层级与苹果官网式 Bento 结构，展示一个清爽、可信、可解释的中文体重管理工具。作品集价值来自清楚的任务路径、真实功能、可访问性和隐私边界，不来自虚构效果、健康评分、评价或承诺。

本轮在用户确认后实现 UI 与分屏交互，不改计算逻辑、不新增业务能力、不引入 UI 框架、不改动线上页面。

## 两种可行的组织方式

### 用户明确的页面方式：分屏单页应用

2026-10-23 补充：用户明确要求首页、资料填写、计划结果分屏显示，按钮切换，不把三者堆在长页面中；切换回顶部，支持保留填写内容返回修改以及浏览器返回。采用现有静态项目内的单页应用（SPA）呈现，保留现有计算和存储模块，不整页重新加载。

好处：第一次使用更清楚；结果、解释与每日行动的优先级更集中；手机不会先经过很长的表单才看见结果。代价：需要处理返回修改、未生成结果、已修改待更新和键盘焦点切换。

### 已排除：单页 Bento 堆叠

曾考虑维持原来的所有内容同页，通过分组折叠、浅色卡片及锚点导航重排。用户已明确不采用此方式；不能只用滚动锚点假装切换界面。

好处：改动量较小，原有锚点更容易保留。代价：首页与工具结果的边界较弱，手机页面依然偏长。

页面切换方式已按用户要求明确；整体方案与视觉稿已由用户确认，进入本地实现。

## 页面切换、历史与草稿规则

页面有三个独立主界面，任意时刻只展示当前界面；非当前界面不占页面高度，也不进入键盘焦点顺序或屏幕阅读器的当前内容。

| 主界面 | URL 片段示意 | 内容与进入方式 |
| --- | --- | --- |
| 首页 | `#/home` | 品牌、简短介绍、Bento 说明、开始入口；点击“开始制定计划”切到填写界面。首页不显示表单或结果。 |
| 资料填写 | `#/profile/basic` | 基础资料、生活习惯、健康情况三步；只显示当前步骤；下一步／上一步切换，最后提交生成。 |
| 计划结果 | `#/plan/overview` | 已生成结果与解释；“修改资料”切回填写界面并保留内容。 |

填写步骤使用 `#/profile/basic`、`#/profile/habits`、`#/profile/health`。结果界面使用“总览／饮食与运动／记录回顾”子面板，对应 `#/plan/overview`、`#/plan/week`、`#/plan/records`；一次只显示一个面板，避免把所有功能继续串成长页面。记录回顾保留体重、打卡、感受和原有数据管理操作，也保留不必先生成计划即可记录的能力。

URL 只包含界面与步骤标识，不放年龄、体重、健康条件等资料。Hash 路由兼容现有 GitHub Pages 静态托管，不需要服务器路由或框架。

- **常规切换**：点击主按钮、下一步／上一步、修改资料或子面板时，更新当前路由，进入浏览器历史，渲染后立即滚到顶部并把焦点移到新界面标题。不会整页刷新，也不会长距离平滑滚动。
- **浏览器后退／前进**：恢复相应的界面、步骤或子面板；按用户要求回顶部，填写内容和已生成结果不被清空。重复进入相同路由不重复添加历史。
- **返回修改**：使用明确的填写路由，不依赖“浏览器上一页一定是表单”的假设。从结果点击“修改资料”，默认打开基础资料组；其余步骤已填值也保留，可直接切换。
- **草稿与结果分开**：当前会话内保留表单草稿及各步骤内容。修改资料不会悄悄重算结果；结果基于上次生成的资料，清楚提示“资料已修改，当前计划待更新”。重新生成成功后才更新结果与原有已保存资料。
- **离开表单**：通过首页按钮、结果入口或浏览器返回离开时，当前会话草稿保留。输入无效时也不丢掉已填原始内容。
- **刷新边界**：普通页面切换和浏览器前进后退保留会话草稿；整页刷新后恢复原有已保存资料和记录，未提交草稿不新增持久化保存。此区别在必要的 UI 提示中说明。
- **直接打开链接**：支持打开已有资料对应的结果路由；没有已生成计划时，显示清楚的未生成提示和填写入口，不把示例伪装成个人结果。未识别的路由回到首页，并替换无效历史条目。
- **已有数据**：不新增存储键、不上传资料、不把路由写进健康数据结构；保持现有生成／更新、记录、打卡、感受、导入与清空的保存规则及多页面保护。

## 首页与填写

首页首屏：轻量品牌导航、简短标题“让健康管理，轻一点。”、一段用途说明、一个主按钮“开始制定计划”。支持卡片只解释现有价值：根据生活条件安排饮食运动、说明建议缘由、在当前浏览器回顾变化。

填写属于独立界面，按三个步骤分屏呈现，短步骤导航支持返回和键盘操作。步骤只是展示与校验分组，不新增草稿持久化。

1. 基础资料：年龄、身高、目前体重、目标体重、计划周期。
2. 生活习惯：平时活动量、运动基础、每次可用时间、每周天数、饮食偏好、器材、场地。
3. 健康情况：保留现有全部可多选条件，展示它们如何影响建议适用范围。

保留真实标签与单位。示例填值显著标注，尚未生成个人计划时不会展示未标注的个人指标。错误出现在字段附近；提交时提供简短错误概览，聚焦首个无效字段，使用 `aria-describedby` 和 `aria-invalid`。

## 计划结果页

结果顶部清楚注明“示例计划”或实际已生成状态。桌面采用有主次的 12 栏 Bento，核心目标／节奏为大卡片；周期、BMI 参考或活动安排使用较小卡片。BMI 标为参考，不制作健康分数、圆环评分或进度百分比。

“为什么适合你”放在核心结果之后，显示来自已有 `why` 的依据：运动基础、时间、场地、器材、饮食偏好与健康条件；保留长文本空间和左对齐。

“饮食与运动”子面板呈现原有一周安排、三餐与替换、热身／动作／休息／放松，以及必要的适用说明；不与全部记录内容同时纵向堆叠。饮食与运动是平级内容区，避免为了 Bento 形状硬截断正文。数据不足或不适用时，相应卡片显示真实状态，原有暂停建议和谨慎分支不会被正常示例卡片替代。

修改资料后显示“资料已修改，当前计划待更新”；主操作变为“重新生成计划”。提交前继续清楚标明当前结果依据上一版已生成资料，避免草稿与结果混淆。保留旧的变化说明以及感受参与调整的方式。

记录区保留现有录入、趋势、打卡、感受、导出导入与清空。主入口能到达真实录入区；完整数据管理放在明确的操作区，导入仍先校验再确认，清空仍二次确认。存储失败和多页面冲突提示维持可见。

## 视觉与响应式

- 背景 `#F5F5F7`，卡片 `#FFFFFF`，正文 `#1D1D1F`。
- 主操作色建议 `#176149`，局部浅绿 `#E8F2EC`，次要正文 `#65686D`。颜色已按确认方案用于本地实现。
- 字体：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", system-ui, sans-serif`。数字启用等宽数字特性，避免跳动。
- 桌面正文 16–18px，手机正文 16px 起；辅助标签也以清楚可读为先。桌面标题约 48–64px，手机 32–40px；指标数字与单位明确分层。
- 卡片圆角 24px，按钮／输入框 12–14px。24–32px 卡片内边距；桌面卡片间距 20–24px，手机约 16px。
- 使用同一组本地线性 SVG 图标；装饰图可使用本地资源或轻量形状。不引入远程字体、图标 CDN 或不必要的图库。
- 卡片层级优先由留白、分组与细分隔体现；阴影轻微。焦点环清楚且不被裁切，输入边框对浅色背景可辨认。
- iPhone 以单列为主，只有简短指标两列；一周选择是至少 44px 的按钮，窄屏时换行。无页面横向溢出，不用复杂固定底栏。
- 点击态使用短暂颜色／轻微位移反馈，约 120–180ms；系统减少动态效果时停用位移和过渡。页面切换时管理标题焦点，表单顺序符合视觉顺序。

## 本轮视觉预览

三张预览属于同一套建议方案：桌面首页、桌面计划结果、iPhone 计划结果。它们是设计稿，不是可点击实现；图中的示例数据均明确标注。当前消息没有附加参考图片，视觉依据为用户提供的苹果风格描述与已捕获的当前网站截图。

视觉稿用于确认层级、布局、配色与气质，不作为字号、像素尺寸、可访问性或功能已验证的证据。手机最终首屏稿优先放大文字并把饮食、运动等内容留给后续滚动，不把整页压缩到一屏。实现时以正文至少 16px、主要触控区至少 44px、无溢出等明确约束为准。

预览中的食物配图只用于表达设计氛围，不是已实现的配餐照片功能；建议实现先复用现有本地图片，并以文本准确呈现各餐，不引入远程图库。具体图标统一为一套本地 SVG。

页面切换补充后的预览解读：首页稿底部的表单移至独立“资料填写”界面；首页不再包含这部分。结果稿中同时展示的总览、饮食运动与记录，是视觉组件的集中展示；实际按上述三个子面板切换。若进入下一轮视觉细化或实现，以本节及“页面切换、历史与草稿规则”为准。
