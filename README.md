# 轻盈计划

个性化体重管理计划静态网页，无需服务器数据库或构建步骤。

本次迭代包括：

- 一周七天的三餐示例与替换食材，支持素食、不吃乳制品和快速备餐偏好。
- 每日热身、具体动作、组数或次数、休息及放松；总时长受可用时间与原有适用范围限制。
- 浏览器本地保存个人资料、体重、饮食与活动／恢复打卡、历次感受。
- 近 7／30／90 天趋势图、按实际日期绘制的体重和过去七天记录均值。
- 补记打卡、连续天数和最近七天统计；同一天的体重或感受重新提交会覆盖该日记录。
- JSON 导出备份、校验后预览并确认导入、确认后清空；存储失败会明确提示，损坏数据不会被静默覆盖。
- 同一浏览器的其他页面更新数据后，自动同步并保留尚未提交的表单草稿；本页存在保存失败的改动且发生冲突时，会阻止覆盖并提示先备份。

## 本地查看

在解压后的目录运行：

```bash
python -m http.server 8000
```

打开 `http://localhost:8000`。为确保本地保存行为一致，请通过 HTTP 地址访问，避免直接双击 HTML 文件。不同域名、端口或浏览器的数据各自独立。

## 数据说明

本地数据存放于 `localStorage` 的 `qingying-state-v1` 键下。资料仅在点击“更新我的计划”后保存，示例资料不会自动成为用户资料。体重、打卡与感受在提交后保存。历史体重不会按一年截断；单类记录校验上限为 10,000 条，导入备份不超过 2 MB。

数据保留在当前浏览器，不上传服务器，也没有账号或云同步。更换设备、清理网站数据或使用无痕窗口前请导出备份。存储不可用时可继续在页面操作并导出，但刷新后可能丢失尚未保存的内容。

一周安排是根据当前资料重新生成的参考模板，历史打卡只保存完成状态，不保存过去食谱或动作快照。活动打卡包含恢复日按身体情况休息。连续打卡允许今天尚未打卡、从昨天开始计算。

最近 14 天内最新的感受参与调整，更早的感受保留回顾。趋势图的均值只使用实际称重，不补零、不插入虚构记录；原有计划建议仍使用至少跨 14 天的粗略变化，并保留身体情况与年龄限制。

## 验证

逻辑测试使用 Node.js 24 的内置测试工具：

```bash
npm test
```

浏览器验证需要本机 Chromium 和 Playwright。在普通开发环境中先安装 Playwright，再运行：

```bash
npm install --no-save playwright
npm run test:browser
```

浏览器测试默认使用 `/usr/bin/chromium`；其他安装位置可通过 `CHROMIUM_PATH` 指定。测试会自行启动临时 HTTP 服务并关闭，覆盖刷新恢复、同日更新、导出、导入取消／确认、清空取消／确认、健康限制、图表范围、多尺寸布局、多页面同步、存储失败和损坏数据保护。生成的 `preview-*.png` 是测试数据下的页面预览，不是用户健康数据。
