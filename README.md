# 轻盈计划

根据个人资料生成体重管理、饮食和运动建议的静态网站。采用系统字体、浅色 Bento 卡片和分屏 SPA，无需数据库、前端框架或构建步骤。

此版本实现已确认的 UI 与分屏交互方案。线上地址：https://kden3995-max.github.io/qingying-plan/

## 页面与操作

- 首页：介绍、开始填写入口，以及明确标注的示例计划入口。
- 资料填写：基础资料、生活习惯、健康情况三步，一次显示一组。
- 计划结果：总览、饮食与运动、记录回顾三个子面板，一次显示一个。

使用 Hash 路由，例如 `#/home`、`#/profile/basic`、`#/plan/overview`，兼容 GitHub Pages。切换时不重新加载页面，回到顶部并聚焦标题，支持浏览器后退／前进。未提交资料保留在当前页面的表单中；修改后显示计划待更新，提交前继续展示上次生成的建议。刷新后恢复已保存资料，未提交草稿不额外持久化。

保留的功能包括：

- 七天三餐示例、替换食材及素食、不吃乳制品、快速备餐偏好。
- 每日热身、具体动作、组数或次数、休息与放松；时长和健康适用范围沿用原逻辑。
- “为什么适合你”的解释，以及原有暂停自动建议和谨慎提示。
- 体重、饮食及活动／恢复打卡、历次感受的本地记录。
- 近 7／30／90 天真实体重趋势、过去七天实际记录均值；无记录时显示空状态。
- JSON 备份导出、校验后预览并确认导入、确认后清空。
- 多页面同步并保留草稿；保存失败后保留可导出的页面数据，发生冲突时阻止覆盖较新记录。

## 本地预览

安装 Node.js 后，在项目目录运行：

```bash
npm run dev
```

打开 `http://127.0.0.1:4173/#/home`。也可以使用 `python -m http.server 8000`，无需安装运行依赖。请通过 HTTP 访问，避免直接双击 HTML；不同域名、端口或浏览器的数据各自独立。

## 数据与隐私

数据仍使用 `localStorage` 的唯一键 `qingying-state-v1`，结构为 `{version:1, profile, records, checkins, habits}`。`app.js` 和 `features.js` 的计算、健康限制、校验与存储算法未改。

个人资料仅在点击“生成我的计划”后保存；查看示例不会保存示例资料。体重、打卡和感受在明确提交后保存，同一天重新提交覆盖该日记录。单类记录校验上限为 10,000 条，导入备份不超过 2 MB。

不上传健康数据，不增加分析追踪、Cookie 或存储键，没有账号或云同步。更换设备、清理站点数据或使用无痕窗口前请导出备份。共享设备的用户共用该站点的浏览器存储，使用后可清空。存储不可用时页面会明确提示，尚未保存的改动在刷新后可能丢失。

一周安排按当前资料重新生成；历史打卡只保存完成状态，不保留过去食谱或动作快照。最近 14 天内最新的感受参与调整，更早的保留回顾。趋势只使用实际称重，不补零、不插入虚构记录；建议仍使用至少跨 14 天的粗略变化。

## 验证

逻辑测试使用 Node.js 24 内置测试工具：

```bash
npm test
```

浏览器验证需要 Chromium 和 Playwright：

```bash
npm install --no-save playwright
npm run test:browser
# 在 GitHub Pages 的 /qingying-plan/ 子路径下验证同样的流程
npm run test:pages
```

默认浏览器路径为 `/usr/bin/chromium`，可通过 `CHROMIUM_PATH` 指定其他位置。测试自行启动并关闭临时 HTTP 服务，覆盖分屏与路由、浏览器返回、草稿、错误焦点、空状态、示例、实际主要流程、存储保护、320–1440px 布局、触控尺寸、减少动态效果和本地资源请求。

截图输出到已忽略的 `artifacts/`，全部使用测试资料。验证说明见 [UI 改版检查记录](docs/ui-redesign-qa.md)。
