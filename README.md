# 轻盈计划

根据个人资料生成体重管理、饮食和运动建议的静态网站。保留系统字体、浅色 Bento 卡片、分屏 SPA，以及原有计算和健康适用限制。

当前版本为**默认内存游客模式**，仅包含第一阶段；未接入登录和云端保存。网站地址：https://kden3995-max.github.io/qingying-plan/ 。发布前检查及回退点见 [发布记录](docs/release-preflight.md)，具体部署结果以对应提交的 GitHub Pages 工作流与线上验证为准。

## 默认游客体验

- 首页、基础资料／生活习惯／健康情况三步、总览／饮食与运动／记录回顾子面板继续分屏显示。
- 资料、体重、打卡、感受及未提交草稿只在当前页面 JavaScript 内存中保留，不自动写 localStorage、sessionStorage、Cookie、数据库或云端。
- 站内按钮和当前体验的浏览器前进后退保留内存草稿；整页刷新、重新打开、跨文档离开、BFCache 恢复或页面冻结后恢复，从空白游客重新开始。
- 所有界面顶部都有“结束体验并清空”，记录区也保留此操作。结束会清除记录、计划、图表、隐藏内容、草稿与待处理的导入，再返回首页。旧历史链接不能恢复已结束的资料。
- 记录功能不因游客模式取消：同日覆盖、删除体重、近 7／30／90 天趋势、打卡补记、感受调整、三餐替换和运动步骤继续可用；刷新后消失是本分支的明确行为。
- 主动打开的示例明确标记，不当作用户资料或称重记录。没有真实记录时显示空状态。

浏览器仍可能保留用户手动导出的下载文件、系统截图或浏览器进程的内部痕迹；结束体验不能替用户删除这些文件。这里的清理指本工具可控制的页面状态与缓存恢复，不是设备安全擦除。关闭／冻结之前没有发生页面生命周期事件的系统行为，以及 iPhone 系统预览画面，需要真机另外检查。

## 旧版数据与手动备份

旧版键为 `localStorage['qingying-state-v1']`。默认只检查键是否存在，**不读取值、不解析、不展示条数或健康字段**。发现旧数据后提示可能属于其他使用者，提供明确的恢复和删除选择。

恢复前必须确认资料属于自己；确认后才读取、校验并替换本次内存，不上传、不合并、不自动归属任何账户。工具无法验证旧副本到底属于谁；不确定时不要恢复。旧副本保留，删除是独立确认操作且只删除这个键，不清空其他站点存储。结束当前游客体验也不会偷偷删除尚未恢复的旧副本。

保留 JSON 手动导入／导出和原备份格式 `{app, exportedAt, state}`，其中 state 仍为 `{version:1, profile, records, checkins, habits}`。导入先校验再确认替换，只进入当前内存；支持旧版备份。原有单类 10,000 条、2 MB 导入限制不变。备份包含健康信息，请妥善保管。

导入失败不改原资料，导出失败有明确提示。结束或离开时，已开始但未完成的文件读取、文件选择器和旧导入确认均失效，不能把上一体验重新带回新页面。

## 本地预览与验证

```bash
npm run dev
```

打开 `http://127.0.0.1:4173/#/home`。也可使用 `python -m http.server 8000`，不需要安装网页运行依赖。

逻辑测试使用 Node.js 24；浏览器测试使用 Playwright 和 Chromium：

```bash
npm test
npm install --no-save playwright
npm run test:browser
npm run test:pages
```

浏览器默认 `/usr/bin/chromium`，可通过 `CHROMIUM_PATH` 覆盖。`test:pages` 在 `/qingying-plan/` 挂载路径下运行全部相同流程。隐私套件显式启用 Chromium BFCache，验证真实 `pageshow.persisted` 恢复；冻结／恢复事件另外做合成事件检查，不能冒充真实系统冻结。

测试输出位于已忽略的 `artifacts/`，只使用合成数据。当前验证结果见 [游客模式验收](docs/guest-mode-validation.md)。既有 UI 设计记录描述的是此前阶段，不代表当前存储策略。

## 第二阶段

[登录＋游客后端方案](docs/login-backend-proposal.md) 提供适合当前静态项目的 Supabase Auth＋Postgres RLS＋Edge Functions 方案、官方价格与限制、会话／账号隔离、删除及配置步骤。

本分支没有接入真实账户、云数据库或假登录入口；A/B 服务端权限、真实退出、云端保存失败和认证过期仍未验证。只有准备好真实测试后端及两个验证身份，并完成服务端权限检查后，才能实现和宣布第二阶段完成。

管理员密钥、数据库密码、SMTP 密码和服务端密钥不得放入网页代码或提交到 GitHub。游客模式不需要这些配置。
